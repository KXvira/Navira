# UI conventions

Navira uses a dark navy canvas (`#08131f`), white primary text, muted blue labels, green for current reliable status, and amber for stale, unavailable, or low precision status. Expo Router supplies one compact header per screen. Tab content does not add a second title or top safe-area inset beneath that header. Tabs use text labels without an icon font; controls have clear accessibility labels and primary touch targets are at least 44 pt high.

The Location screen has a compact status panel and responsive measurement cards. Freshness and reported horizontal accuracy are separate: a fresh update with accuracy above 100 m is amber and explicitly marked low precision, while the original number remains visible. Missing accuracy is never treated as zero. This display threshold does not affect waypoint saving or freshness. Waiting, receiving, stale, permission-denied, services-disabled, and error remain distinct. Last measurements remain visible with their age when stale.

The Satellites tab uses a virtualized, compact row list. It shows Android GNSS phase, age, reported count, and used-in-fix count above the list. Counts and rows are hidden when a snapshot is stale. An accessible Info action explains C/N₀ and the limits of GNSS provenance; Expo Go shows native diagnostics as unavailable without affecting location readings.

The Waypoints tab keeps a Save action and saved-place list near the top. A selected destination appears as a compact summary that opens a focused guidance view. Guidance shows straight-line distance, initial true-north bearing, and current/saved reported accuracies. It pauses when current location is stale or unavailable. Waypoint detail viewing, editing, and saving are separate stack routes. Deletion always uses a platform confirmation alert. Longer technical explanations are available through accessible Info actions.
