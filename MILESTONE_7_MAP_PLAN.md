# Milestone 7 plan — local spatial view, then managed offline coverage

Status: 7A local spatial view implemented in source; native GitHub build and device acceptance are separate gates. No tile source, provider, download, or INTERNET permission has been added. Research checked on 2026-10-03 against [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/), [MapLibre React Native](https://maplibre.org/maplibre-react-native/docs/setup/getting-started/), and provider terms below.

## Milestone 7A implementation

The app uses `@maplibre/maplibre-react-native` 11.4.1 with Expo 57, React Native 0.86.3, and React 19.2.3. Those versions satisfy the library's documented minimums; only a successful native build establishes integration with this project. The bundled style has only a background layer and no URL, source, sprite, glyph, or tile references. The map labels the absence of a street/terrain basemap. Saved waypoint markers, saved route line segments and single-point anchors, and a fresh current-location marker are in-memory GeoJSON. The route geometry uses the same eligibility function as GPX: legacy, anchor, and counted samples. It groups by persisted segment index and never draws a line across a quality-excluded segment break. Excluded samples are not shown as map geometry. Map reads through the existing app hooks, makes no storage writes, and does not alter recording or totals. Waypoint and route details open the map as a focused route; pan, pinch zoom, Fit route, and Recenter are available. Recenter is available only with a fresh Expo Location reading, and the screen shows age and reported accuracy.

7A acceptance still requires a signed native APK build and owner device testing. Check the final APK manifest for no INTERNET, background location, or foreground service permission. Check airplane mode/Wi-Fi off, route breaks, waypoint and route detail entry, fit/recenter, fresh/stale marker, accuracy text, relaunch, and unchanged saved distance/GPX. No map data attribution applies to the blank local style; MapLibre library attribution remains in project notices. 7B coverage remains a separate decision requiring rights, pack format, asset completeness, and a deliberate INTERNET policy if downloads are chosen.

## Recommendation and architecture

Use MapLibre React Native for the map renderer, after a small native-build compatibility spike on SDK 57 / React Native 0.86 and the signed Android workflow. Its v11 documentation requires the New Architecture and React Native 0.80 or newer, includes an [Expo config plugin](https://maplibre.org/maplibre-react-native/docs/setup/expo/), and exposes [offline packs](https://maplibre.org/maplibre-react-native/docs/modules/offline-manager/). Those requirements match Navira on paper but do not establish that this exact build works. MapLibre is open-source software under a permissive [license](https://github.com/maplibre/maplibre-react-native/blob/main/LICENSE.md); map **data**, styles, fonts, icons, and hosting have separate terms and costs.

Keep the map screen and renderer adapter separate from route recording and SQLite. Read waypoints and saved route points through existing repositories, convert to in-memory GeoJSON, and draw point markers plus one LineString per **exportable distance segment**. Excluded policy 2 samples may appear as clearly different diagnostic markers, never as a line that reconnects segments. Show the current Expo Location reading only when fresh, with its reported accuracy and age. Do not feed map camera or map gestures into recording logic. Do not transmit live coordinates.

Phase 1 uses a local, plain background/style with waypoint, saved-route, and current-location geometry; it works without a basemap or `INTERNET` permission. Phase 2 adds user-selected offline coverage from a licensed tile source or a legally provisioned local pack. Coverage has explicit bounds/zoom, estimated and actual size, download/import progress, completion and missing-area state, attribution, last update, and delete controls. The style manifest, vector/raster tiles, glyph/font ranges, sprites/icons (including high-DPI variants), and any terrain resources must all be available offline; cached tiles alone do not make a complete offline map. MapLibre styles reference separate [sources](https://maplibre.org/maplibre-style-spec/sources/), [glyphs](https://maplibre.org/maplibre-style-spec/root/), and [sprites](https://maplibre.org/maplibre-style-spec/sprite/).

## Data source and permission decision

The current `app.json` **blocks `android.permission.INTERNET`**. Keep that block for phase 1 and for any offline packs imported from local files. An in-app coverage download cannot work while it remains blocked. If the owner chooses in-app downloads for phase 2, explicitly remove the block in app config, require a new native build, inspect Expo config and the final APK manifest, and show a user-initiated region/zoom download action. Do not send live coordinates; tile requests still reveal the selected coverage area to the provider, so disclose that separately.

Do not use the public `tile.openstreetmap.org` service for offline packs: its [tile policy](https://operations.osmfoundation.org/policies/tiles/) expressly prohibits bulk downloads and offline use. OSM **data** is available under ODbL with [attribution obligations](https://www.openstreetmap.org/copyright), but that is distinct from the community tile server. Prefer licensed, locally provisioned vector packs if Navira must operate without any app network permission. Generation/import format, style asset packaging, ODbL attribution, redistribution rights, storage budget, and compatibility with MapLibre's offline database require a prototype before choosing a pack supplier.

For optional user-managed downloads, Stadia Maps is a plausible provider to evaluate: its [terms](https://stadiamaps.com/terms-of-service/) allow limited mobile offline caching up to **100 MB per device**, and its [offline guide](https://docs.stadiamaps.com/tutorials/offline-maps-with-flutter-maplibre-gl/) requires an active subscription and cache revalidation when possible. Its [current pricing](https://stadiamaps.com/pricing/) charges by plan/credits; the free plan excludes commercial use. Confirm that the selected plan, style, attribution, and complete asset set cover the intended regions and use before implementation. MapTiler Cloud is not an interchangeable bulk-download source: its [cloud terms](https://www.maptiler.com/terms/cloud/) prohibit bulk downloading absent an agreement. Provider logos/attribution must remain visible online and offline.

## Phased scope and dependencies

1. **Spatial display:** install and build-test MapLibre with `npx expo install`; add an Expo Router map view, a renderer adapter, in-memory repository-to-GeoJSON conversion, accessible layer toggles, fit-to-content, and an offline plain-background fallback. Preserve existing location subscription and route persistence. No tile requests, map download, or permission change.
2. **Coverage prototype:** test one legally sourced local vector pack or a provider-approved small offline pack on the Samsung A16. Check styles, glyphs, sprites, attribution, storage size, restart persistence, and true airplane-mode rendering. Decide between local import and explicit network download based on rights and the INTERNET policy.
3. **Managed coverage:** add named regions, explicit select/import/download, size estimate and cap, progress/error/retry, list and delete, update/revalidation when online and licensed, incomplete-coverage indicator, and no automatic prefetch. Keep map data storage separate from waypoint/route SQLite and never modify recorded geometry to fit a map.

Dependencies before phase 2: a compatible native MapLibre build, documented map-data and style rights, a pack format and asset manifest, storage limits, attribution text, and an explicit decision on whether `INTERNET` may be unblocked. The 7A map package and local view do not add a map-data provider or permission.

## Device acceptance criteria

- On the signed Android APK, waypoints and each saved route segment appear at the expected positions; excluded policy 2 observations do not form connecting lines. Legacy routes remain visible without rewriting their totals.
- Current location appears only while fresh, with reported accuracy and stale state; map viewing does not start recording or a second location subscription. Satellite status remains separate from Expo Location.
- With airplane mode on and Wi-Fi off, the phase 1 spatial view works. In phase 2, a completed licensed coverage pack renders at its advertised zoom/bounds after relaunch; outside coverage is clearly marked, with no silent network fallback.
- Coverage import/download, pause/retry, storage-cap handling, deletion, style/font/icon rendering, and attribution work on device. For an online-download variant, inspect the final APK manifest for deliberate `INTERNET` and continued absence of background-location/service permissions.
